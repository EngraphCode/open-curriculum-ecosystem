# The public explanatory system — an arriving reader is answered

## Outcome

A person who arrives at the repository learns, from the README's first paragraph, what it is, who
it is for and where it stands, and reaches a page that answers their question in one click. No page
an outsider reads contradicts another, Oak's own site, or the code.

The owner's standard, 2026-11-13, verbatim: the README "should function as a professional class
readme for a major repo of a respected AI and digital service organisation", and "Ministers may
look at this, CEOs, CTOs, devs, educators, journalists. The explanatory system, of which the readme
is the entry point, needs to satisfy the highest standards."

## User groups and value

The value is offered, not proven: no reader research exists, and whether these readers arrive at
the README at all is unverified.

- **Teachers**: a way out to Oak's own page for connecting an assistant, on the first screen.
- **Ministers and their advisers**: what this is, whose it is and where it stands, in thirty
  seconds, with nothing false in it.
- **Journalists**: statements that hold when checked against Oak's site and the commit history,
  and a route to ask.
- **Chief executives**: what it changes and on what terms it can be used.
- **Chief technology officers**: whether it can be built on, from the architecture, the security
  policy and an honest account of what is published.
- **Developers**: a start that works from a fresh clone.
- **Connected assistants**: the orientation skill routes them to the README and the vision, so
  those pages are an input to the product.

## The bet

The pages decayed by accretion: each lane recorded its own change on the front page, each addition
was reasonable alone, and nobody owned the reader's side. Seven separate lanes added to the README
on the fork between August and October 2026, measured against Oak's copy. Giving the reader's side
an owner (this node) and a stated standard holds better than another rule; the rules already
existed.

The standard every public page is held to:

- **Where each kind of fact lives.** What is Oak's to state (what Oak is, whether the service is
  live, which assistants, privacy, safety, accessibility, impact, contact) lives on Oak's site;
  the repository links to it, or quotes it once with the source. What the code knows (counts,
  whether a package is published) appears only in a generated, checked home. What is written once
  here has one home, and other pages link to it by name and carry no count.
- **The first paragraph is the whole story** for the least technical reader, and nothing but the
  title precedes it (`.agent/directives/editorial-tone.md`).
- **Routes by what the reader came to do**, with a way out on the first screen for anyone the page
  is not for.
- **Public copy is assembled from approved wording and read by the owner as rendered** before its
  pull request opens; it is never invented.
- **A public page links to nothing in working material**: plans, the backlog, reports, threads or
  state.
- **A front page is not a notice board.** A notice lives in the record that owns the decision.
- **Instructions are run from a fresh clone before they land.**

Deliberately not done: a rendered documentation website; any page that restates what Oak
publishes; a rewrite of the strategy pages, the decision records or the Practice Core.

## Success looks like

The owner reads each public page as GitHub renders it and finds nothing to correct. A reader
simulation starting from the README alone answers each reader's questions within their time. The
reference-direction check blocks a public page that links into working material. This node does
not claim that readers are better served in fact; only reader evidence could show that.

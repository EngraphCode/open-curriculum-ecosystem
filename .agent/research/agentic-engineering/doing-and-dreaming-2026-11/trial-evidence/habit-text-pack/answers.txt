**Draft text:**

```markdown
---
classification: core
description: "Before any file-mutating action (Edit, Write, mv, sed -i, codegen output), confirm the target path is the right file in the right checkout and is not a generated projection."
---

# Confirm the Edit Target Before Editing

## Trigger

Immediately before any action that mutates a file: an Edit or Write tool
call, a shell `mv`/`cp`/`sed -i`/redirect, or a script that writes output.

## Action

Before the mutating call, confirm three facts about the target path:

1. **Right checkout.** The absolute path sits under the checkout this session
   resides in (the lane worktree, or the principal for a principal seat), not a
   sibling worktree or the principal reached by a stale `cd`. Use absolute paths;
   never rely on the shell's current directory surviving between calls.
2. **Right file.** The path is the file read this session, not a same-named
   sibling (a canonical rule vs its platform adapter, `src/` vs `dist/`, a live
   doc vs its archived copy). If the file should not exist yet, confirm the
   parent directory is the intended home.
3. **Not a projection.** The file is not generated. Generated surfaces
   (`RULES_INDEX.md`, `.claude/rules/*`, `.agents/rules/*`, `.cursor/rules/*`,
   codegen output) are changed at their source, then regenerated.

If any of the three cannot be confirmed from a read made this session, read
first; do not edit on recall.

## Failure mode prevented

An edit that lands in the wrong worktree, on a lookalike sibling, or on a
generated file that the next regeneration silently overwrites. The edit
"succeeds", so nothing signals the miss until a gate, a reviewer, or a lost
change surfaces it.

## Evidence and falsifier

Observation count: n = <count after verification>, from <cited napkin entries>.
Falsifier: if wrong-target edits recur with this rule loaded, prose is not the
cure. Replace it with a PreToolUse path guard on Edit/Write.

## Enforcement

Behavioural. Partial structural backstops already exist: the platform's
read-before-edit requirement on the Edit tool, and the worktree-isolation guard
that refuses principal-path edits from a worktree-resident session.

## Related

- `verify-dont-trust` (file paths are artefacts to inspect)
- `worktree-residency` (absolute paths; the cwd-reset signal)
- `generator-first-mindset` (change the generator, not the output)
```

# Instructions judged to bear on each task

Every instruction not listed under a task was marked N for all six answers to that task.

## Task 1: handle a Copilot comment (rename a helper, add a fallback value)

Answers: A01, A05, A20, A22, A25, A26

- **precedence-is-not-approval**: a reviewer's verdict is exactly the kind of prior verdict the instruction says is never authority by itself.
- **verify-dont-trust**: the instruction names reviewer statements as claims to check against concrete artefacts (here the callers and types) before acting.
- **replace-dont-bridge**: a rename can leave an alias for the old name, and a fallback value is a fallback path, both of which the instruction forbids.

## Task 2: plan a new always-on rule about double-checking a file path

Answers: A02, A09, A17, A18, A21, A29

- **one-instance-is-an-observation**: a new rule is a named rule derived from observed incidents, so the instance count governs whether it can be written.
- **re-apply-first-question-at-elaboration-boundaries**: the plan must ask whether a cheaper home (a clause in an existing rule) would do the same job.
- **compute-dont-hope**: the rule index and platform adapter files restate facts held in the canonical rule file, so the plan must generate them, not hand-keep them.
- **verify-dont-trust**: the plan makes claims about where files go and what tooling does, which need checking against the repository or flagging as unchecked.
- **scope-from-goal-before-approach**: a plan is the moment the instruction asks for a restated goal and an In/Out surface set.
- **design-work-for-small-prs**: the instruction places PR sizing at plan-shaping time, which this is.
- **present-verdicts-not-menus**: the analysis ends in a choice between a new rule and an amendment, so the answer must give a recommendation, not hand the choice back.

## Task 4: draft a commit message and git commands for a one-line README fix

Answers: A04, A08, A11, A14, A15, A19
